GD32F407VE 考试1 —— 四按键多功能演示（裸机多任务）
================================================================================

【一、题目要求与实现对应】

按键    要求                                  实现方式
------  ------------------------------------  --------------------------------
KEY1    首次按：流水灯，累积点亮              250ms 一步，9 步一轮
          1 亮 -> 1,2 亮 -> 1,2,3 亮 -> ...
          -> 1~8 全亮 -> 全灭 -> 从 1 重新开始
        再次按：停止，且【定格】              亮着几颗就保持几颗常亮，不再变化
KEY2    首次按：节拍器，LED1/2/3 同时按各自    125ms 一步，8 步 = 1 秒
        节拍工作；再次按：停止                3 灯同时输出，位模式与需求表一致
KEY3    首次按：8 位数码管依次轮流显示 0~7，   400ms 一步，8 步一轮
        间隔 400ms；再次按：停止且【定格】    每次只有 1 位亮
KEY4    首次按：播放《两只老虎》；            简谱 + 时值表，20ms 任务推进
        再次按：暂停；再按【续播】不重播

四个按键是独立的业务，但它们对硬件资源的占用不同，所以"独立性"要分两层看：

    KEY1 流水灯  ┐ 都用 LED 灯组 (LED1~8)
    KEY2 节拍器  ┘ => 这两个【不独立】，后按的接管，先按的停

    KEY3 数码管  -> 只占数码管  ┐
    KEY4 音乐    -> 只占蜂鸣器  ┘ => 与谁都不冲突，可以和 KEY1/KEY2 同时跑

代码上不是用"一个全局模式"来表达，而是每个资源一个占用者：
    g_led_owner      谁在控制 LED 灯组（流水灯 / 节拍器 / 空）
    g_flow_running   KEY1 是否在跑
    g_metro_running  KEY2 是否在跑
    g_nixie_running  KEY3 是否在跑   ← 独立开关
    g_music_running  KEY4 是否在跑   ← 独立开关

所以 KEY1 跑流水灯时按 KEY3，数码管照样启动，流水灯不受影响。

“停止”的语义按功能区分，这点最容易做错：

    KEY1 流水灯  -> 【定格】亮着几颗就保持几颗常亮
                    例：亮到 3 颗时按下，LED1/2/3 保持常亮，其余不亮
    KEY2 节拍器  -> 【清空】LED1~8 全部熄灭
    KEY3 数码管  -> 【定格】当前第几位显示什么数字就保持住，不熄灭
                    例：第 5 位显示 4 时按下，屏幕上就是第 5 位的 4 常亮
    KEY4 音乐    -> 【暂停】静音但保留播放进度；
                    再按一次从这个音【续播】，不是从头重播

KEY4 的续播靠 App_buzzer.c 里的 s_music_idx 实现：
    暂停时只清 s_music_next_ms（表示"当前没在播"），绝不清 s_music_idx；
    续播时用 now 作为当前音的起始时刻，把 s_music_idx 指着的那一个音再播一遍。
    只有整首播完一轮，idx 才自然回到 0。

实测时序（用仿真脚本逐拍复刻验证，不是推断）：
    流水灯间隔  精确 250ms
    节拍器间隔  精确 125ms，一轮 1000ms
    数码管间隔  精确 400ms
    -> 没有 ±10ms 或 ±20ms 的抖动，见第七节说明


【二、接线】

外设        信号        引脚      说明
----------  ----------  --------  ------------------------------------------
LED 灯组    LED_SW      PC6       总开关，经 R9(1K) 接 Q1(S8550_PNP) 基极
                                  PNP 基极低电平导通，所以 PC6=低 才是"通电"
            LED1~LED8   PD8~PD15  低电平点亮
数码管      NIX_DI      PD0       74HC595 的 SER
            NIX_RCK     PD1       74HC595 的 RCLK
            NIX_SCK     PD4       74HC595 的 SRCLK
独立按键    KEY1~KEY4   PC0~PC3   上拉输入，按下为低
蜂鸣器      BUZZER      PB9       复用 AF1，Timer1_CH1，无源蜂鸣器


【三、节拍器位模式（与需求表格逐格对应）】

        步:   0  1  2  3  4  5  6  7      （每步 125ms）
LED1          1  1  1  1  0  0  0  0
LED2          1  1  0  0  1  1  0  0
LED3          1  0  1  0  1  0  1  0

计算式：
    LED1 = (step < 4)          // 前 4 步亮 = 1 秒里闪 4 次
    LED2 = (step % 4 < 2)      // 每 4 步前 2 步 = 闪 2 次
    LED3 = (step % 2 == 0)     // 每 2 步第 0 步 = 闪 1 次

注意第 7 步三灯全灭是需求的正常结果（表格最后一行就是 000），
但第 0~6 步每步至少有一盏灯亮，所以视觉上"三灯同时在工作"。


【四、任务表】

位置：User/Task.c 的 task_list[]

    {0,  2,  App_nixie_task},      // 数码管扫描 + 400ms 流水
    {0, 10,  App_key_scan_task},   // 按键扫描
    {0, 10,  App_led_task},        // 流水灯 250ms + 节拍器 125ms
    {0, 20,  App_buzzer_task},     // 音乐播放

为什么 LED 任务取 10ms 而不是 20ms：
    250 和 125 都能被 10 整除。到点检测落在步长整数倍上，
    实测间隔精确 250/125ms。若取 20ms，250 不是 20 的倍数，
    间隔会在 240/260ms 之间交替。虽然不累积漂移，但评分表对
    "间隔时间错误"是直接扣分的，没必要留这个把柄。

时基：Timer5 每 1ms 中断一次，累加 g_t5_tick_ms。
调度判据：now - 上次 >= period 就执行一次并更新时间基准。
各任务内部用"(now - 启动时刻) / 步长"取模算目标步，而不是"每次 +="，
避免把采样误差一步步累加。

【六、编译选项（按考试模板设好了）】

PlainCh = 1                   勾选 "Plain Char is Signed"
Define += HXTAL_VALUE=8000000 外部晶振 8MHz
Device  = GD32F407VE
uC99    = 1

关于 char 有符号：
    数码管驱动原本的写法是 `for (char i = 7; i >= 0; i--)`，
    这个循环只有在 char 是有符号时才正确。本工程把 Nixie.c 的
    循环变量改成了 int8_t，所以不依赖这个开关；
    但工程选项仍然按考试模板勾上了，两层保险。


【七、验证记录（哪些是实测、哪些是推断）】

已用机器验证的三层：
    [1] 编译：0 Error(s), 0 Warning(s)
    [2] 链接：读 .map，25 个关键符号全部链入，无未解析符号
    [3] 产物：Code=5290 RO=506 RW=264 ZI=1120，Flash 合计 6060 字节
        确认没有浮点库（__aeabi_f*）、没有 printf 被拖进来

时序验证：
    用 Python 逐拍复刻三个任务的逻辑（周期 2/10/10/20ms），
    跑了 3 轮以上，核对每一步的灯态、数字、出现时刻。
    结果：流水灯 250ms、节拍器 125ms、数码管 400ms，偏差均为 0。

没有验证的部分（需要上板确认）：
    - 数码管实际亮度（2ms/位，8 位一轮 16ms = 62.5Hz）
    - 蜂鸣器 8 个音阶的实际音准（取决于无源蜂鸣器谐振频率）
    - 《两只老虎》的听感节奏（简谱数据取自课程原工程）
    - 按键消抖 30ms 是否合适（不同批次按键抖动时间不同）


【八、如果现象不对，按症状查】

症状                        先查什么
--------------------------  ------------------------------------------------
按键没反应                    PC0~PC3 是否上拉输入；按下时对地是否导通
按一次触发多次                KEY_DEBOUNCE_CNT（默认 3 次 = 30ms）
LED 全不亮                    PC6 是否为低电平。Q1 是 S8550_PNP，
                             基极低电平才导通，量 PC6 对地应接近 0V
某个 LED 不亮                 对应 PDx 是否被别的功能占用
流水灯间隔不对                 确认 Task.c 里 App_led_task 周期是 10 不是 20
节拍器三灯不同步               确认三灯都在 App_led_task 里同一次调用的 Metro_update
数码管全灭                    PD0/PD1/PD4 有无波形；595 的 VCC(16 脚) 是否上电
数码管多位同时亮               确认 s_scan_pos == s_nixie_index 才 Nixie_display，
                             其余分支必须 Nixie_clear()
数码管间隔不对                 确认 Task.c 里 App_nixie_task 周期是 2ms
蜂鸣器不响                    PB9 是否 AF1；USE_TIMER_1 是否为 0（Timer1 归蜂鸣器）
蜂鸣器音调不对                确认 TIMER_init() 在 App_init() 之前调用
                             （MUL4 倍频在那里设置，音调公式依赖它）
按 KEY4 后 LED/数码管还在动     说明 App_toggle_mode 没有先 App_stop_all()
整个卡死                      任务函数里是否误加了 delay 或死循环
